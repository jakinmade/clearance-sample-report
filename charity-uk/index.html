This is what a UK charity receives after a CLEARANCE diagnostic of an AI system that is already live. The example is a wildlife charity that has run an AI propensity model in its supporter CRM for nine months. It scores supporters for regular-giving upgrades and legacy likelihood, suggests ask amounts, and uses appended wealth and geodemographic data. Its selection rules are documented and enforced, a fundraiser can override any score, a named staff member owns the system, and vulnerable-supporter safeguards are in place, but six controls are missing. Each finding fires only when a specific control is absent. An AQE sample for the same fictional charity shows the check before extending the model to legacy prospects.

High risk

No gap blocks deployment outright, but no trustee is minuted as accountable for the model, there is no documented basis for profiling donor data this way, and the charity could not produce a tamper-evident record of why a given supporter was selected.

What was found

Each gap fires only when specific answers are present, and the report shows which ones. For each, the report states what it looks like when it goes wrong and the first thing to do about it.

SeverityGap and what it looks like in practiceFirst action
HIGHNo trustee accountability structure for AI-assisted charitable decisionsThe Charity Commission opens an inquiry and asks which trustee was accountable for an AI-assisted grant decision. The charity has no answer.Name a trustee owner this week. Minute it at the next board meeting.
HIGHNo compliant data governance for AI processing of Gift Aid donor dataA donor submits a Subject Access Request. The charity cannot identify or retrieve what an AI system processed about them using their Gift Aid declaration data.Map what donor data your AI systems access this week. Confirm the lawful basis for each processing activity.
HIGHAudit voidA client disputes a decision and asks to see the record. The decision happened. The record of it did not.Start logging every decision this system makes today: date, input, output, rule applied, in a write-once store. This is the foundation. Every other governance control depends on it existing.
HIGHNo process for handling data subject rights in AI systemsAn employee contests an automated decision about them, which is their right under UK GDPR. There is no process on the other end to receive that challenge, only silence.Map every AI system holding personal data into the data subject rights response workflow. Document the Article 22C human review process. Implement the DUAA 2025 complaints mechanism.
MEDIUMProvenance weaknessA regulator or auditor asks where the data came from that drove a specific decision. Tracing it back takes days, not minutes, and for some inputs there is no trail at all.Create a register of every data source feeding this system. Assign an owner and a validation status to each.
MEDIUMPersonal data used by AI beyond its original collection purposeSomeone asks why their data ended up feeding an AI system they never knew existed. The honest answer is that it was collected for something else entirely, and no one checked whether feeding it to this system was still compatible with that original purpose.Identify every AI processing activity using data beyond its original collection purpose. Complete a compatibility assessment for each under DUAA 2025 Article 8A. Update privacy notices before the next data collection cycle.
